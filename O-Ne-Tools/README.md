## 使用方式
1. 開啟 `index.html`。
2. 在入口頁選擇要製作的字卡。
3. 各編輯器可直接輸出 PNG；是否含背景依工具設定。

## 最近 5 次編輯與載入 JSON

- 目前 13 個可用／候選工具都只有按「暫存目前內容」才新增紀錄；平常輸入、切換選項、還原版本與載入 JSON 都不會暗中儲存。
- 每個工具只保留同一瀏覽器最近 5 次不同內容；相同內容重複按暫存不會新增一筆。
- 未按暫存就重新整理或關閉時，會回到最後一筆已暫存內容；載入 JSON 後也要再按一次「暫存目前內容」才會寫入紀錄。
- 關閉視窗或重新開機不會刪除暫存；清除該網站的瀏覽器資料、無痕模式結束或換裝置則不會保留。
- 每個工具都有「最近編輯與 JSON 載入」區塊。從清單選一筆後按「還原」，即可回到該次內容。
- 要跨裝置備份時，可繼續使用工具原有的「輸出／下載設定 JSON」；之後在同一種工具按「載入 JSON」並選擇該檔案。
- 載入檔限制 1 MB，且必須是同一工具的 JSON。格式錯誤、工具不符或欄位無效時會拒絕載入，畫面目前內容不會被覆蓋。
- 評分卡、焦點卡、縮圖品牌框與片尾結算卡的單獨 JSON 只保存文字與圖片調整設定，不直接嵌入圖片位元；若要連圖片一起搬移，使用下方 ZIP 專案包。說明卡則使用該工具自己的 `.onecard` 專案檔保存圖片本體與每張裁切設定。

共用行為由 `edit-backup-v1.js` V1.2.0 提供；各工具仍保留自己的正式 JSON schema 與驗證規則。常駐卡沿用既有本機暫存鍵值，其餘工具也不更換原鍵值，因此升級前的最近紀錄不會被清除。

## 智慧檔名與完整 ZIP 專案包

- PNG、JSON 與專案 ZIP 統一使用「卡片分類-標題-狀態」，不再加入 `O-Ne` 前綴，例如：`焦點卡-道頓堀觀光船-步驟-含字.png`、`常駐卡-大阪城任務-成功.json`。
- 狀態會依目前卡片變體自動判定，例如成功／失敗、可愛、白色／橘色、接受／放棄、含字／空框；同標題的不同版本因此可直接區分。
- 檔名中的 `/ \\ : * ? " < > |` 與控制字元會自動清理；標題空白時使用「未命名」。
- 13 個可用／候選工具都有「完整專案包」區塊，可下載或載入 `.zip`。
- ZIP 會包含：目前預覽 PNG、專案設定 JSON，以及使用者在該工具置入的圖片檔；圖片放在 `assets/` 子資料夾。
- ZIP 專案 JSON 使用 `o-ne.project-package.v1`，會記錄 tool id、標題、生成器版本、設定快照與圖片欄位對應；載入時會拒絕其他工具的專案包。
- 圖片回填使用穩定欄位 ID／名稱／語意位置；焦點卡這類動態左右圖片欄位會先還原版面狀態，再把原圖回填到正確側，最後重新套用裁切／縮放設定。
- 專案包目前上限 200 MB，採自包含 ZIP，不依賴外部 CDN；舊 JSON 與最近 5 次暫存機制維持相容。

共用專案包與檔名由 `project-package-v1.js` V1.1.0 提供。12 個共用備份工具由 `edit-backup-v1.js` 自動接入；常駐卡因保留既有自訂暫存 UI，直接掛載同一個 project package helper。

片尾結算卡的欄位與安全框定義另見 `settlement-card-mapping.json`；挑戰卡四個 state 與正式 PSD／PNG 對照見 `challenge-card-mapping.json`。正式 PSD 只作來源，生成器不會覆蓋 Drive 母檔。

## 同卡種批次出圖

- 13 個可用／候選工具共用 `batch-render-v1.js` V1.1.0，會在「完整專案包」下方顯示「批次出圖」。
- 同一次批次只接受目前工具的檔案，最多 20 份、總量 200 MB；可混選 `.json` 與 `.zip`。
- 純文字工具可直接批次讀取原本 JSON；評分卡、焦點卡、說明卡、縮圖品牌框、片尾結算卡等圖片型工具，批次模式要求使用 ZIP 專案包，避免輸出缺少置入圖片的殘缺 PNG。
- ZIP 若含專案包內建 PNG，批次會直接取用該 PNG；沒有 PNG 時才開啟隱藏同頁工作器重新套用設定並渲染，不會覆蓋目前正在編輯的畫面。
- 批次前會逐份驗證卡種與格式，顯示「可輸出／請改 ZIP／格式錯誤／卡種不符」；錯誤檔不會混入輸出。
- 完成後只下載一個 `字卡名稱-批次輸出-YYYYMMDD.zip`，裡面是依「卡片分類-標題-狀態」命名的 PNG；同名檔自動加 `-02`、`-03`。
- 可按「停止」中止後續處理；已完成的 PNG 仍會打包下載。

## 給 AI 的 JSON 格式提示

- 13 個正式可用／候選工具共用 `ai-json-guide-v1.js` V1.0.7；每張卡的「給 AI 的 JSON 格式」與右側預覽卡放在同一欄，緊接於預覽卡下方；左側編輯／暫存／ZIP／批次區不會被插入此說明。說明卡的含圖片交付改依該工具現行 `.onecard`，不再誤寫成 ZIP。
- 格式直接依目前各工具真正的 JSON exporter／importer 整理，不另造第二套 schema。
- 每張卡提供「複製完整 AI 指令」「複製 JSON 範例」「下載 JSON 範例」；完整 AI 指令會要求 AI 回傳 UTF-8 `.json` 檔，若介面不能建立附件則只回 raw JSON，不加 Markdown 程式碼框或解說。
- 說明區會列出固定 component/schema、重要 enum、陣列數量與其他必要限制；移動卡等結構型工具也會提示站點／路段等相依規則。
- 評分卡、焦點卡、說明卡、縮圖品牌框與片尾結算卡會明確標示：JSON 不包含使用者置入圖片位元；需要連圖片一起交付時使用 O-Ne 專案 ZIP。
- AI 產生的 JSON 仍必須由對應工具「載入 JSON」驗證；格式錯誤或卡種不符時，不得視為正式可用檔。

## 全工具視覺硬規則
- **主底板／卡體底色固定 80% 透明度（opacity = 0.80）。**
- 只有底板底色套用 80%；**不是整張卡片一起 80%**。
- 外框、狀態標籤、識別色條、圖示、文字、選項列與其他前景元件維持各自正式透明度，不得跟著整體變淡。
- 新增任何字卡工具時，必須先檢查此規則再標示可使用。

## 工具入口整理原則
- 一個功能只留一個入口。
- 移動卡不另拆跨國版，跨國需求用每段實線／虛線處理。
- 選項卡不另拆 2 項版；可自由增減選項，每一項可獨立切換亮／暗，允許同時亮多項。
- 挑戰卡不拆接受／放棄頁；接受／放棄與 YES／NO 選取都在 `challenge-card.html` 內切換。
- 觸發卡 EVENT／DONE!／FAIL 在同一編輯器切換。
- 常駐卡 MISSION／DONE!／FAIL 在同一編輯器切換；任務文字與進度字級由使用者手動控制，超出正式安全寬度時阻擋輸出並提示調整；JSON 可備份並載入還原。
- 對話卡已確認為正式卡，後續整合 Omi／涅特／Kuma／Nomi／NPC／雙人與表情選擇。
- 玩家 1 為移動卡同系藍色，玩家 2 為紅色。
